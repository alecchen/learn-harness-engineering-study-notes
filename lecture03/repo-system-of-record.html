The knowledge visibility gap

Project knowledge missing from the repo correlates with agent failure. Every gap is a question the agent has to guess at.

Agents need answers to four questions
How is it organized?
How do I run it?
How do I verify it?
What's the current progress?

~/lecture03/notes/minimal.md

Minimal but complete

The guardrail behind every file in the canonical repo: enough to act on, nothing to drown in.

Too little
Agents guess - no run, no verify, no status.
Just right
Complete enough to act on. The 50-100 line target.
Too much
Walls of prose - agents skim and miss the load-bearing line.

~/lecture03/notes/acid-analogy.md

The repo as a database: ACID

The lecture maps database guarantees onto repo discipline.

Atomicitycommit only complete work; nothing to roll back
Consistencydefine predicates, verify after each operation
Isolationconcurrent agents equal concurrent transactions
Durabilitygit-tracked knowledge survives session death
~/lecture03/notes/acid-caveats.md

Where the analogy breaks

In a database, ACID is enforced by the system. In a repo, none of it is automatic.

ATOMICITY
git stash is not a rollback
A rollback erases the failed attempt; a failed commit leaves nothing to roll back.
CONSISTENCY
Mechanism, not property
Verification is a mechanism; consistency is the state it enforces.
GUARANTEES
Nothing is automatic
Databases enforce ACID; a repo relies on manual discipline.

~/lecture03/notes/missing.md

What the lecture leaves out

Agents writing backThe repo as record implies write access; the lecture never discusses it.
Git history as recordgit log tracks migrations and renames - grep for migrate, rename, consolidate.
What stays outSecrets, build artifacts, machine config, large binaries, ephemeral notes.
The mirror test: regenerable, confidential, or machine-specific? Keep it out.
